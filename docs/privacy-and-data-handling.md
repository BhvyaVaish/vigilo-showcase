# Privacy Architecture & Data Handling Practices

This document provides a transparent, factual disclosure of how data is captured, processed, stored, and transmitted within the **Vigilo** prototype application.

To maintain professional compliance and avoid false assurances, **no unsupported claims of regulatory certification (e.g., formal GDPR, HIPAA, or ISO/IEC certifications) are made**.

---

## 1. Inventory of Handled Data Categories

Vigilo processes several categories of potentially sensitive user and vehicular information:

| Data Category | Specific Data Elements | On-Device Usage | Off-Device Transmission |
| :--- | :--- | :--- | :--- |
| **Location & Kinematics** | GPS coordinates (Latitude, Longitude), Altitude, Speed, Bearing, Horizontal Accuracy. | Used to determine vehicular speed drops and establish crash scene location. | Transmitted via SMS to user-designated emergency contacts during an uncancelled alert. Included in Gemini advisory prompts if AI reporting is invoked. |
| **Inertial Telemetry** | Triaxial Accelerometer readings ($m/s^2$), Gyroscope angular velocities ($rad/s$), computed Jerk ($da/dt$). | Continuously ingested at 50Hz into a temporary circular buffer (FIFO, last 50 samples) to detect impact shocks. | In the event of an impact, the peak snapshot is saved locally to SQLite. Telemetry metrics are submitted to the Gemini API for advisory report generation. |
| **Emergency Contacts** | Names and telephone numbers of up to 5 user-selected personal contacts. | Stored in local app settings (`SharedPreferences` / Room) to identify SMS recipients. | Contact phone numbers are used as SMS destinations via Android `SmsManager`. Never uploaded to any central cloud server. |
| **Video Evidence** | Short post-impact video clips recorded from the device's rear camera. | Saved locally to device storage (`DIRECTORY_MOVIES/Vigilo`). Digest is computed and signed via Android Keystore. | **None.** Video files remain local by default. They are not uploaded to the Gemini API or cloud servers. |
| **Acoustic / Speech Data** | Real-time microphone audio during the 10-second alert window. | Evaluated in real-time by Android's `SpeechRecognizer` (`EXTRA_PREFER_OFFLINE = true`) to detect *"I'm okay"* or *"I need help"*. | Audio is processed via the platform speech service. Audio samples are **not** persisted to disk or stored in incident records. |

## 2. Local-First Processing Boundaries

1. **Zero Cloud Dependency for Core Safety:** All detection algorithms, gravity isolation filters, circular buffers, TFLite inference, countdown timers, and cryptographic signatures execute entirely on the local device.
2. **Ephemeral Sensor Buffering:** Raw 50Hz sensor data is held in an in-memory ring buffer (`CircularSensorBuffer`). Samples older than the buffer capacity (~1 to 2.5 seconds) are continuously evicted and overwritten; normal driving motion is never saved to persistent storage.
3. **No Passive Surveillance:** Drive monitoring requires explicit user activation by tapping **"Begin Drive Monitoring"**. Vigilo does not record background video or track continuous GPS history during normal driving.

## 3. Cryptographic Verification Scope & Legal Boundaries

Vigilo employs the **Android Hardware-Backed Keystore** (TEE / StrongBox) to generate an ECDSA key pair and sign a canonical string of incident facts, alongside a chunked SHA-256 hash of the video file.

### What SHA-256 & Digital Signatures Prove:
* **Integrity (Tamper Detection):** It mathematically proves that the saved telemetry numbers, coordinates, and video bytes have not been modified, edited, or corrupted since the digital signature was generated by that specific device's hardware keystore.

### What Cryptography Does NOT Prove:
* **Physical Authenticity of Origin:** A cryptographic signature does not verify whether the phone was mounted to a car or thrown onto a bed by hand.
* **Absolute Universal Time:** The timestamp is tied to the smartphone's internal system clock at the moment of signing, which can drift or be manually adjusted if network time protocol (NTP) sync is disabled.
* **Unbroken Chain of Custody:** While the hash detects file tampering, legal chain-of-custody admissibility in court requires formal forensic verification of the physical device and export procedures.

## 4. Cloud AI Data Disclosure (Google Gemini API)

* When the user requests an AI-assisted narrative report, a structured summary of numerical telemetry (Peak G, Gyroscope rad/s, Jerk, Speed, Speed Drop, and Onset Explanation) is sent to Google's Gemini API over HTTPS.
* **User Control:** If an API key is not supplied, or if the device is offline, the feature is disabled, and Vigilo falls back to a deterministic offline note without transmitting data.
* **No Video/Audio Upload:** Raw video recordings and acoustic voice data are **never** transmitted to the Gemini API.

---

## 5. Security & Access Control Recommendations

Because incident data and video evidence are stored on local device storage:
1. Devices running Vigilo should maintain full device encryption (Android default on modern devices) and a secure lock-screen PIN/biometric challenge.
2. In production deployments, incident video files should be written to app-isolated private internal storage (`context.filesDir`) rather than public media directories to prevent unauthorized access by other installed applications.
3. Users retain the ability to delete individual incident records or clear the entire incident history database at any time from the Incident History screen.
